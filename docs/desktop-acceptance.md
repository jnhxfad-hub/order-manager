# 桌面端验收脚本

这个脚本用于把桌面 App 的关键链路变成可重复验收流程。它不会用坐标点击 UI；它负责准备唯一测试数据、先备份当前真实库，并在桌面操作完成后自动查询 SQLite 复核结果。

## 准备验收数据

```bash
pnpm run desktop:acceptance -- prepare
```

脚本会在 `/private/tmp/order-manager-desktop-acceptance/<run-id>/` 生成：

- 客户导入 CSV。
- 商品导入 CSV。
- 订单明细导入 CSV。
- 当前真实库的预备份。
- `manifest.json`。
- `runbook.md`。

## 桌面操作

按生成的 `runbook.md` 在 release App 里完成：

1. 客户导入。
2. 商品导入。
3. 商品分配客户。
4. 新建订单并导入明细。
5. 下单。
6. 可选 OCR 人工抽查：在批量入库弹窗选择入库图片，检查图片预览、旋转、识别结果、OCR 原文和重复图片跳过提示；抽查后关闭弹窗，不确认入库。
7. 普通批量入库。
8. 首次部分出库并打开预览，确认余额保留且入库、调整和公共库存转入已锁定。
9. 再次创建出库单，确认单号依次为 `订单号-01`、`订单号-02`。
10. 将全部剩余库存手动转入客户库存，确认订单库存完结。
11. 新增客户库存批次并创建单批次客户库存出库单。
12. 新增两个客户库存批次并创建合并客户库存出库单。
13. 设置页手动备份。
14. 使用刚生成的备份恢复。

客户库存批次的历史下单日期使用日期选择器，也支持直接输入 `YYYY-MM-DD`，例如 `2026-06-20`，便于桌面验收时稳定录入指定日期。

合并客户库存出库的重量必须按批次绑定填写：批次 A（较早历史日期）填写喷涂重量 `11 kg`、出库 `2` 支并使用“第一车”；批次 B（较新历史日期）填写喷涂重量 `12 kg`、出库 `3` 支并使用“第二车”。客户库存列表按历史日期倒序时，界面第一组通常是批次 B、第二组通常是批次 A，不要按界面组序号反填重量。

OCR 人工抽查不参与自动复核；普通批量入库仍是自动复核的入库路径，避免识别效果受图片质量和系统 Vision 环境影响。

## 自动复核

```bash
pnpm run desktop:acceptance -- verify --manifest /private/tmp/order-manager-desktop-acceptance/<run-id>/manifest.json
```

复核内容：

- 客户已导入。
- 商品已导入。
- 商品已分配给客户。
- 订单已创建且状态为 `ordered`。
- 订单明细匹配商品、模具、长度、颜色和数量。
- 首次部分出库后订单余额仍保留，第二次出库仍可创建。
- 两张出库单编号为 `订单号-01`、`订单号-02`，数量和重量分别正确。
- 首次出库后订单入库、调整和公共库存转入被锁定。
- 手动转客户库存后订单库存为 `0`，订单状态为“剩余转客户”。
- 订单转入的客户库存批次保留 `source_order_id`、订单日期、价格、费用、规格和备注快照。
- 库存流水包含 `produce +6`、`ship -2`、`ship -1` 和 `transfer_customer -3`；客户库存流水包含 `transfer_order +3`。
- 客户库存单批次出库单已创建，单号为 `批次号-01`。
- 客户库存合并出库单已创建，单号为 `客户首字母-CK日期-01`。
- 客户库存合并出库单关联两个批次，客户库存出库单列表应显示“合并”；单批次出库单应显示“单批次”。
- 客户库存合并出库单保留两个计价方案及各自喷涂重量。
- 桌面 App 手动备份文件存在。
- 恢复前安全备份已生成。

## 注意

- 验收必须运行 release App：`src-tauri/target/release/bundle/macos/铝材订单管理系统.app`。
- 如果要从 `/Applications/铝材订单管理系统.app` 启动，必须先用本次 release bundle 覆盖旧 App。
- 验收前先关掉旧 App 进程，避免误操作旧包。
